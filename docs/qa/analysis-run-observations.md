Add entries whenever run monitoring surfaces something worth acting on; move an item to Resolved when it ships. ## Attack list

Ordered by expected impact.

1. **Queue hold before sources land.** The uniqlo run sat 32s between `generation.started` and `source.found` while the wait surface showed Queue. Part is dispatch (below), part is plan plus early fetch running before the first source event. Two angles: emit an earlier Gather-worthy event (`plan.ready` currently maps to no stage; mapping it to Gather splits the hold), and shrink the real pre-source work. UI mapping change is cheap; measure first whether the hold is common (query `research_run_events` gaps).
2. **Inngest dispatch latency: RESOLVED for user-facing runs (2026-07-23, inline dispatch).** Baseline was mean 13.6s, p50 7.5s, outliers 47s and 73s, and an Inngest Cloud incident on 2026-07-23 held two organic runs 290s and 188s in a dead Queued (see run log). Basics and analysis now execute in-process in the `/api/generate` invocation; production first event is ~1.9s after the 202 (see Resolved). Residual scope: section jobs and the enrichment workers still ride Inngest dispatch, where the latency is invisible to the user; no further action unless that changes.
3. **skip-fresh promotion: DONE (2026-07-22, promoted).** Samay approved on 15 prod-parity pairs: claims 31 to 31 net zero (4 drops, 6 ties, 5 increases, every drop traced to synthesis non-determinism), citations down 5.2% with zero gate impact, AgentCash 100% eliminated, wall down 10.1s median. `ANALYSIS_SOURCE_REFRESH=skip-fresh` is live in Vercel production; rollback is removing the var. The two-week measurement watches citation counts as the tripwire.
4. **Targeted-mode dedup optimism.** The unpromoted `targeted` refresh mode ignores the Direct Exa coverage dedup, so its projected savings are slightly high. Only matters if `targeted` or the skip-fresh stale fallback ever promotes.
5. **Transient-vs-semantic step-failure classing: partial.** Wave 1 shipped `isTransientLlmError` (`packages/llm/src/transient-error.ts`) and wired it into the synthesize-card and verify-synthesis steps (`generation-helpers.ts`, commit `1a8e44e`): a transient 429/5xx/network failure now re-throws so Inngest retries it instead of permanently memoizing a failed step. Residual closed same day: the `generate-section` step now applies the same split (re-throw transient, memoize semantic), wired by inspection against the tested wave-1 pattern since the inline closure has no cheap unit seam.
6. **sidepanel-ui Playwright project is deliberately manual-only.** `npm run qa:extension:ui` (`playwright test --project=sidepanel-ui`) is not part of `apps/extension`'s `test` script, so it never runs inside `npm run check` or CI; it is a by-hand pre-merge gate. The fly-by intent-gate rework (commit `890fa0d`, stop racing wall-clock time against the budget) makes that manual gate trustworthy again instead of flaky. Keep treating it as manual, not automated.

## Run log

- **2026-07-27, three-day outage found and fixed: every post-insert card write failed from 2026-07-24 onward.** Two failure classes killed 17 of 18 analysis attempts across 8 companies (codex, adaptivesecurity, cadastral, corner, drinkpoppi, varda, economist, usb) and every contact and block enrichment on fresh cards. Class one: `mutateCard` compared `updated_at` for optimistic concurrency, but a fresh insert leaves that column to the Postgres default (microsecond precision) while a JS Date reads back milliseconds, so the equality never matched and all 32 retries threw the misleading "concurrent writes" error; 14 failures, zero real contention (economist failed with its card untouched for hours). Fixed by migration 0011's `version` counter; the compare now uses it, and existing stuck cards healed on their first post-deploy write with no repair script. Class two: the synthesis model returned `{"text": null}` inside `marketStructureAndTiming.profitPool`, the schema demanded a string, and the run died after paying for synthesis (varda twice, adaptivesecurity once); a null-text claim now normalizes to an absent claim, extending the 2026-07-22 container fix one level down. Four adjacent fixes shipped in the same pass: block-enrichment failures now emit `enrichment.failed` instead of stamping `generation.failed` onto completed basics runs (usb run 8256b1bc, codex run 2feaf273 carried the misleading trail); repeat section requests answer from a settled deep run instead of dispatching a second paid job (drinkpoppi billed twice for customer_proof ten seconds apart, runs 41acd320 and 4c21de53); run errors store a readable sentence with the raw validation issues moved to the trace; and `alpha:status --gate` now scans every generation run instead of only alpha-linked ones, because the pre-fix gate reported "Failure codes: none" against this exact window (all traffic is operator-token and was invisible to it). Verified on production after deploy: economist (9 claims verified, 4 survived), usb (8 of 9 survived), varda (verifier killed all 11 and stored the honest `no-claims-survived` withheld verdict, proving the null-leaf fix held), and fresh-company mews end to end (basics 39.6s, block enrichment landed, contact enrichment found 3 work emails, 3 person reads present, analysis 57.9s with synthesis stored, zero failure events). Post-deploy traffic is clean; the 7-day gate keeps failing on the historical window until it rolls, which is the alarm working. Skip-fresh latency after the fix: p50 53.8s, p90 57.9s (n=11), under the bar. This bug class was a hard blocker for alpha invitations: every friend's second interaction with any company they researched would have failed.
- **2026-07-23, inline dispatch shipped: user-facing runs no longer wait on Inngest.** Basics and analysis execute in-process in the `/api/generate` invocation (kept alive past the 202 by `after`, route `maxDuration` 300s), behind `GENERATION_DISPATCH` with `inngest` as the rollback value; rows record the path in `inngest_run_id` (`inline:` prefix). Deployed verification on resend.com: basics `generation.started` +1.89s from the 202, sources and early read +9.1s, complete in 44s at $0.0095; analysis started +1.94s, `synthesis.started` +2.3s on skip-fresh reuse, verified read stored, complete in 48.5s at $0.0425. Two accepted deltas: no step memoization inline, so a verify failure that exhausts the one transient retry fails the run and a re-click re-pays synthesis (~$0.03-0.08); a run outliving 300s dies with the instance, and the new request-path watchdog retires any `running` row silent for over 5 minutes (card event seen means complete, else failed) so the next click starts fresh instead of joining a corpse for the 15-minute stale window.

## Resolved

- Silent synthesis withholds (11 of 51 runs): fixed by Phase 1's floor-plus-advisory gate and visible withheld state, deployed 2026-07-21.
- Per-tick full-card polling waste: event-gated since Phase 4 (`de8d048`).
- The 50s event dead zone during synthesis and verify: real events since the Phase 4 step split.
- Verifier truncation exposure: `max_tokens` raised from 2000 to 8192 in `verifier.ts:116`, 2026-07-23.
- All-claims-dropped runs presenting as expensive, non-converging failures: the run now converges instead of throwing, storing a `no-claims-survived` withheld card when no prior read exists or preserving an existing read otherwise (issue #10), 2026-07-23.
- Inngest dispatch latency for user-facing runs (attack item 2): basics and analysis run in-process in `/api/generate` since 2026-07-23; production first event 1.9s against the old 7.5s p50 and the 290s incident hold. Section jobs and enrichment workers stay queue-dispatched.
- Post-insert card writes always failing ("Failed to update card after concurrent writes" on every fresh card): the timestamp-precision compare in `mutateCard` replaced by a version counter, migration 0011, deployed 2026-07-27. Killed 14 analysis runs and all fresh-card contact and block enrichment over 2026-07-24 through 2026-07-27.
- Null-text timing claims killing paid analysis runs: a claim whose text is null normalizes to an absent claim whatever sits in citationIds, extending the 2026-07-22 container normalization one level down, deployed 2026-07-27 (varda twice, adaptivesecurity once).
- Block-enrichment failures misattributed as `generation.failed` on completed basics runs: the worker emits `enrichment.failed` since 2026-07-27, mirroring the contact worker's `contacts.failed`.
- Duplicate paid section jobs on repeat requests: the route answers from a settled deep run inside its staleness window since 2026-07-27; derived rows and failed or stale sections still dispatch.
- Raw Zod issue dumps in the run error column and event messages: validation errors store one readable sentence since 2026-07-27, with the structured issues in the trace failure block.
- `alpha:status --gate` blind to operator-token traffic: reliability and the software-failure and stale-run gate checks scan every generation run in the window since 2026-07-27. The pre-fix gate reported zero failures against a window holding 17.
